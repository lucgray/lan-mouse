## 结论与 90 分标准

目前不能认定达到 90 分：原始审查发现的按键释放、返回路径和图片单向问题已按表内范围修复，但一般队列拥塞、原生后端阻塞、真机往返及长期资源验收仍未闭环。下方原始清单保留当时问题证据；源码实现和完整验收分开记录。没有完整实测依据，不编造当前综合分。

建议采用以下验收评分；未验证项不计“通过”。90 分还必须满足所有 P1 问题关闭，不能用界面优化抵消失控风险。

| 维度 | 权重 | 通过依据 |
|---|---:|---|
| 输入与返回正确性 | 35 | 队列拥塞、断续恢复、双向切换均不丢释放事件；1000 次往返无失控 |
| 延迟与资源 | 25 | 固定硬件下记录基线；局域网输入端到端 p95 ≤20ms、p99 ≤50ms；8 小时 RSS 无持续增长；静态剪贴板不反复编码 |
| 剪贴板体验 | 20 | 文本/图片两个连接方向、断线后同步、失败提示及最新内容顺序测试通过 |
| 故障反馈与恢复 | 15 | 界面正确区分待连接、已发送、已应用和失败；不需要用户靠重启恢复 |
| 配置可靠性 | 5 | 写入失败不破坏配置，监听能恢复，用户能收到保存失败提示 |

这些数值是提议的验收目标，不是已测性能。测试时需记录鼠标回报率、网络 RTT/丢包、显示刷新率、CPU 和系统版本。

## 第一轮：输入正确性与失控恢复

### R01 / P1：watchdog 删除返回边缘，输入恢复时不重建

- [ ] 修复并验证。
- 证据：`src/emulation.rs:273` 超时发出 Disconnected；`src/service.rs:652` 删除 incoming capture；后续 Input 在 `src/emulation.rs:486` 自动重建 emulation handle，却不发 Entered。
- 影响：输入恢复但无法通过原连接返回。已有现场日志支持，详见 `timeout-return-barrier-issue.md`。
- 建议：区分按键清理与会话销毁，保证恢复时输入状态和返回边缘一致。
- 验收：虚拟时间触发 watchdog，保留 DTLS，恢复普通 Input/Ping 而不发 Enter，仍可返回；真正断开也能完整清理。

### R02 / P1：Windows 队列满时丢弃键盘/鼠标按钮事件

- [x] 新增 InputBudget / InputLease：全局 256 条、每接受连接 64 条，lease 从读取后的普通 Keyboard/Pointer 和 Enter 帧随 Msg 带到代理消费。结束消费、旧会话过滤、禁用/丢弃或超时均释放额度；idle reader 不占额度。
- [x] 一次入队等待共享 250ms 期限，取消能直接打断；持续饱和时停止该 reader、取消其会话 token、从实际连接表移除、发一次 InputOverloaded 前端失败提示、Disconnected 并有界关闭 transport。使用已有 pressed-key 和返回边缘清理，不把被拒绝的 key-up 静默忽略后继续旧会话。
- [x] 正常 FIFO 不合并、不改协议，其他连接有独立每会话额度并共享总额。此轮不声称整个进程所有队列有界。

### 四个回归与验证

- [x] 跨 peer 共用总额，单 peer 无额不阻止另一 peer 使用剩余额度；总额耗尽时失败等待会归还已持有 peer 额度；取消和 drop 无泄漏。
- [x] 实际 read_loop 使用默认额度及无限重复键释放帧：只排队 64 条，250ms 期限后恰好一次过载反馈及 Disconnected，token 取消、连接移除/关闭；丢弃队列后总额回到 256 / 64。
- [x] reader 持有最后一个 Enter lease 并继续请求额度时，取消不等待测试中的 60 秒 admission 期限；按 200ms 外部保护内完成，容量恢复。
- [x] 实际代理请求循环把输入交给永久 Pending 后端时，已转发 lease 仍占用额度；后端操作 deadline 错误返回后才释放，新的合法请求可获额度。
